## Tool Details
- **Name:** Embiggen
- **Repo:** ben-gy/embiggen
- **Category:** image-tools (index category: images)
- **Audience:** Anyone with a too-small image and a reason not to upload it — marketplace sellers,
  designers handed tiny logos, people restoring low-res photos.
- **Stack:** Vite 6 + vanilla TypeScript + Vitest
- **Browser APIs:** WebGPU (+ WASM/ONNX Runtime fallback), @huggingface/transformers (Swin2SR
  image-to-image), Web Workers + comlink, OffscreenCanvas, File System Access, Web Share, Clipboard,
  Service Worker (PWA)
- **Worker strategy:** single dedicated ES-module worker over comlink; one Swin2SR pipeline per
  scale, lazily loaded; streams determinate model-download progress.

## Privacy Model
- **Protected:** the image and the result — decoded, upscaled and delivered entirely in the tab.
  No accounts, no cookies, no watermark, no telemetry of files.
- **Not protected:** first use of a scale downloads that ONNX model (~50–130 MB) from huggingface.co
  (HF sees an IP, never the image); ordinary page-load metadata; cookie-less Cloudflare Web Analytics
  page view; feedback only if the user sends it.
- **Trust surface:** the commit-pinned static bundle, the TLS chain, the Swin2SR weights fetched once
  from Hugging Face, and transformers.js + ONNX Runtime (Apache-2.0 / MIT).

## Architecture Decisions
- **Two models, lazy-loaded:** `Xenova/swin2SR-classical-sr-x2-64` (2×, sharp on clean sources) and
  `Xenova/swin2SR-realworld-sr-x4-64-bsrgan-psnr` (4×, robust on real/compressed photos). Only the
  chosen scale is downloaded. Swin2SR was picked over GAN upscalers because it is faithful (high
  PSNR) rather than hallucinatory, and it has known-good official transformers.js ONNX conversions.
- **Output-bound planning (`planUpscale`, unit-tested):** the transformers.js `image-to-image`
  pipeline does not tile, so it holds the whole image in memory. Oversized inputs are proportionally
  pre-scaled so the result lands within a 4096 px bound — bounding memory without hurting the primary
  small-image use case. Output is exactly `work × scale` (Swin2SR has fixed integer factors).
- **ORT WASM is bundled by Vite (~21 MB) but excluded from PWA precache** (globPatterns omit `wasm`);
  only the app shell + JS is precached. Model weights come from Hugging Face, HTTP-cached.
- **CSP** extends the standard tool policy with huggingface.co / *.hf.co / cdn-lfs in `connect-src`
  for the one-time model fetch; `wasm-unsafe-eval` in `script-src`. Cloudflare + feedback origins kept.
- Vanilla TS (single linear workflow, no React needed).
