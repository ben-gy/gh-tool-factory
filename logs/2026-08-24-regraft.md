## Tool Details

- **Name:** regraft
- **Repo:** ben-gy/regraft
- **Category:** image-tools (`images` in the public index)
- **Audience:** someone who generates images locally — ComfyUI, A1111/Forge, InvokeAI, NovelAI — and has
  just found that the picture they want to iterate on came back from a chat app without its graph.
  Secondarily, anyone wanting to know what a picture is quietly carrying before they repost it.
- **Stack:** vanilla TypeScript + Vite 6, strict. **Zero runtime dependencies.**
- **Browser APIs:** Compression Streams (`DecompressionStream` deflate + gzip, `CompressionStream`
  deflate), module Web Worker, transferable `ArrayBuffer`, `Blob` (structured-clone by reference),
  `navigator.share({files})`, `navigator.clipboard`, Service Worker, Web App Manifest
- **Worker strategy:** one dedicated module worker; every byte-touching operation runs there and the
  main thread does DOM only. Progress is throttled by timestamp, never `requestAnimationFrame` — rAF
  does not fire in a backgrounded tab and has hung this fleet before.
- **Storage:** none. No IndexedDB, no OPFS, no localStorage. A build gate asserts it.

## Privacy Model

- **Protected:** the image is read and rewritten in-tab and never uploaded; recovered prompts (which
  routinely name clients, people and local paths) are rendered via `textContent` only and never
  logged, persisted or sent; every `console.*` is dropped at build time; nothing is written to disk.
- **Not protected:** a grafted file carries the recipe *by design*; regraft is not a metadata remover
  and never claims a file is free of anything (the word "clean" appears nowhere in the product);
  overwriting the pixel plane changes the picture by one level per affected sample; an absent recipe
  proves nothing.
- **Trust surface:** the static bundle over GitHub Pages' TLS, the browser's own Compression Streams,
  the Cloudflare Web Analytics beacon (anonymous page views), and feedback.benrichardson.dev if and
  only if the user opens the form and presses Send.
- **Honesty gate:** regraft makes no claim about whether an image was AI-generated. The "what ComfyUI
  will see" column is labelled a prediction everywhere it appears and is dated to the reader it
  emulates (2026-08-23).

## Architecture Decisions

**A first-party PNG codec, and why the three obvious libraries were all rejected by measurement.**
`png-chunks-encode` builds a boxed JS array with one element per byte and CRCs every chunk including
`IDAT`: 1 MB → 367 ms, 8 MB → 27 s, 20 MB unfinished at 120 s, against ~1.2 s to rebuild 60 MB here.
`png-chunks-extract` throws on any CRC mismatch — which loses precisely this tool's core population,
the damaged file whose text is intact. `png-chunk-text` is `tEXt`-only and Latin-1-only in both
directions. The distinctive engineering claim is not "reads a bit-plane" (veilpix does that) but that
this is the fleet's first tool with a first-party PNG codec: veilpix round-trips through canvas, which
premultiplies alpha and is colour-managed by Safari, and is therefore structurally unusable here.

**The graft preserves original CRC bytes rather than recomputing them,** and copies untouched chunks as
byte ranges. That is what makes "the image data is byte-for-byte identical" checkable rather than
asserted — and it is checked, by re-parsing the output with a parser that knows nothing about the plan
that produced it.

**The pixel scan streams.** Detection reads the first 152 pixels column-major; extraction retains only
the columns the declared payload spans, with a two-row unfilter window. A whole-image materialisation
was measured at 16.6 s and two coexisting 244 MB buffers for a 64 MP image.

**Re-filtering uses the original per-row filter types, never filter 0.** Measured on a 1600×1200 RGB
PNG: original IDAT 1,422,151 B; LSBs cleared with original filters 1,102,890 B; with filter 0
**2,409,556 B** — 2.19× worse, for free, since the filter bytes are already in the inflated stream.

## The critical defect the review found

An 11-agent adversarial review ran over the inherited engine across four lenses (PNG codec, stealth
pixels, ops/verdicts, robustness/privacy), each finding attacked by an independent refuter instructed
to default to *refuted*. Seven findings were raised; three were refuted; **four survived, and all four
were the same defect, found independently by all four lenses:**

> `src/stealth/stealth.ts` set `DETECT_PIXELS = SIGNATURE_BITS` (120), but `scanStealth` reads
> `SIGNATURE_BITS + LENGTH_BITS` = 152 bits before it will report a hit. In **alpha** mode the carrier
> is one bit per pixel, so a 120-pixel window stops 32 bits short of the length field: `bitAt` returns
> −1, `readBits` returns null, the mode is skipped, and the tool reports **"No generation recipe in
> this file"** for a file that plainly has one. Alpha is the plane **NovelAI writes by default**. RGB
> mode carries three bits per pixel and so covered the header by accident — which is exactly why a
> fully-covered unit suite never saw it.

It fired on the shipped flagship sample (`stealth-alpha.png`, the one-click "Recover it from the
pixels" demo). One agent verified the payload independently in Python/PIL, swept 1,765 geometry
combinations (740 unreadable with the shipped constant, 0 with the fix), and confirmed 15/15 alpha
cases were false negatives while 16/16 RGB cases passed.

Fix: `DETECT_PIXELS = HEADER_BITS`. Verified by reintroducing the bug and confirming the new tests fail.

**The generalisable lesson: every part was individually correct and the assembly was wrong.** The unit
suite covered `unfilterRow`, `readBits`, `matchStealthSignature`, `scanStealth` and `planeWindowFor`
and all of them passed. Nothing tested the constant that wires them together. Hence the new
end-to-end file.

## Three further defects, found only in the browser

None of these would have been caught by a scripted DOM assertion, which is the point worth recording:

1. **`src/styles/main.css` was never imported.** The entire tool rendered unstyled. Every scripted
   check still passed — including the full four-exit overlay test — because the DOM was correct and
   only the presentation was gone. It surfaced by *measuring* a close button's hit area: 36×30 instead
   of the required 44×44, and a `getComputedStyle` probe then showed the page had no `.icon-btn` rule
   at all. The build gate now asserts a stylesheet is emitted, is linked from `index.html`, carries the
   `[hidden]{display:none!important}` guard, and contains this tool's own overlay rules.
2. **The chunk table printed "image data, after the image data"** against every `IDAT` after the first
   and against `IEND`. `afterIdat` is the right test for a text chunk a reader may never reach and
   meaningless for those rows. Added `afterIdatNote()`, used by both the table and the Markdown report.
3. **The fixed event-log pill covered the primary call-to-action** at 375px, and the footer's Feedback
   link when scrolled to the end. The pill is now compact on mobile and both surfaces have clearance.
