## What the research changed before a line was written

13 agents, 1,332,283 subagent tokens, six lenses each attacked by an independent refuter. The
refutations changed the product, not just the code.

1. **The spec's primary feature is the minority case.** Measured over 10,988 fenced blocks in real
   multi-block programming answers: **3.82% carry a recoverable path, 96.18% do not.** unfence is
   therefore not a path *recovery* tool with an assignment fallback — it is a path *assignment* tool
   with recovery as an accelerator, and the queue with typeahead over the enumerated tree is the
   primary surface. Built that way.
2. **Two of the spec's four conventions are phantoms.** `title="src/app.ts"` and `=== path ===`
   scored **zero** hits in 26,911 real blocks. The "35 separator hits" that justified the latter
   decompose to 37 **bold-line** hits, because the separator regex's delimiter class included `*` and
   swallowed `**src/app.ts**`. Both are kept — five lines, cannot false-positive — but the two that
   actually fire were absent from the spec entirely: Copilot Chat's mandated `// filepath:` comment
   and Aider's bare first line.
3. **The truncation rule had to be derived twice.** Brace balancing is undecidable here
   (`registry.json` finishes at depth +2 because of a brace inside a string; a Babel generator
   finishes at −1). The proposed replacement — regex the line at `token.map[1] − 1` — fails 4 of 23
   controlled cases and produced **44 false truncations in 105 flags** on a real corpus. What ships is
   arithmetic inside markdown-it's own coordinate system, `closed = (map[1] − map[0]) >= n + 2`,
   verified 23/23.
4. **Elision cannot be detected from the block.** Simulating the modal case over 359 real files, the
   obvious "new file is under half the size" rule catches **one**. The gate is the shape of the diff.

## Architecture decisions

- **Vanilla TypeScript.** The state is a linear workflow, not a component tree.
- **Four runtime dependencies, each chosen against a measured alternative.** `markdown-it` because a
  naive `/^```/m` scanner is wrong on nine of twelve real CommonMark cases and sees **zero** fences in
  a fence inside a list item, which is the dominant shape of a multi-file answer. `diff@9` because
  3 KB gzipped buys byte-identical-to-git output on the two hardest cases. `client-zip` because
  `predictLength()` is byte-exact, which is what makes the backup *verifiable*. `fflate` to read a
  dropped zip, which is the universal input path.
- **No runtime tokenizer.** Exact o200k counting costs ~800 KB brotli by every route measured, on the
  plumbing half of the tool. A per-extension divisor table (~19 numbers) lands within ±9% at the 90%
  level and is labelled `≈` with its band shown.
- **No three-way merge.** `--3way` implies `--index`, which refuses the dirty working tree this tool's
  premise guarantees, and on conflict writes merge markers unfence has no git to clean up.

## Measurements this build made for itself

- Token divisor table re-fitted over **2,170 hand-written files, 18 repositories, six languages,
  27.4 MB, 8,184,534 real o200k tokens**. Bundle-level error over 500 simulated 200-file bundles:
  bytes÷4 p50 **−16.1%** (worst 29.3%), one global divisor p50 +0.3%, the shipped table p50 **−1.4%**
  (p5 −9.0%, p95 +5.2%, worst 12.6%). `.json` splits by kind: lockfile 2.60, authored data 3.18.
- `git apply` strictness, against git 2.50.1: wrong hunk **counts** → rc=128; wrong hunk **starts** →
  tolerated; missing final newline → rc=128; CRLF patch → rc=1; zero context → rc=1. Hence the four
  artefact invariants.
- `git apply` refuses `../../escape.txt`, `.git/hooks/pre-commit` and `.GIT/hooks/pre-commit`
  (rc=128) and **accepts** `.github/workflows/ci.yml` (rc=0) — so that refusal is unfence's alone.
- A CRLF file against an LF reply of identical text: **one hunk of 10,000 lines** on a 5,000-line
  file, and a 4 ms diff becomes 2 seconds.
- `client-zip` `predictLength()` byte-exact (3,244 predicted = 3,244 actual); no compression.

## Bugs the build caught on itself

Three of these were found in the browser, not by the unit tests, and one by CI.

1. **`createTwoFilesPatch` cannot express a deletion** — `git apply` returns **rc=0** and leaves a
   **zero-byte file**. The test asserts on file size, because the exit code is exactly what misses it.
2. **The space-in-path tab is a post-process.** Passed as `oldFileName` it makes diff@9 C-quote the
   whole path (a tab is a byte < 0x20) and git answers `No such file or directory`. Appended after
   formatting — never to an already-quoted path — it applies under both `git apply` and BSD `patch`.
3. **`applyHunks` got four trailing-newline cases wrong**, caught by cross-checking every result
   against what real git produced.
4. **Escape did not close the modals.** The buttons filled the body and removed the `hidden` attribute
   directly, so the overlay was never on the stack the document-level Escape handler reads. The `×`
   and the backdrop both worked; **3 of 16 exits failed silently.** Found by the mandatory
   escape-hatch test, fixed by deleting the second code path.
5. **Two blocks assigned to the same path produced two `+++ b/...` create stanzas**, which `git apply`
   refuses outright. `collapseDuplicates` runs in the parser and never sees a user assignment.
6. **A bare first-line path was written into the file it named** — a created `src/validate.js` began
   with the text `src/validate.js`, a syntax error in every language. Aider's convention puts the
   filename *in* the block as metadata; only the `filepath:` marker was being stripped.
7. **`Newtonsoft.Json` passed the pathlike gate** — `.json` is a known extension and the check was
   case-insensitive. A no-slash candidate now needs an all-lowercase extension, which also kills
   `System.Text.Json` and `PIL.Image`.
8. **The iOS notice fired on a desktop Mac.** The standard iPadOS heuristic
   (`MacIntel && maxTouchPoints > 1`) false-positives under emulation and on any touch-capable Mac. It
   is now gated behind the absence of `showDirectoryPicker`.
9. **A literal control byte in a helper script** (a NUL written as a space) silently skipped every
   file containing a space during the divisor fit — the recurring factory trap, hit again.
10. **The `keepExistingData` gate fired on the comment explaining the rule** — the docxray lesson,
    repeated. The gate now strips comments first.
11. **CI caught what the local run could not:** `git config --get core.ignorecase` **exits 1** when the
    key is unset, and git only sets it on a case-insensitive volume. On macOS it reads `true`; on the
    Linux runner it threw and took the whole suite down.

  2 into the queue.

  collapsed to the later version.
- **The patch the running browser produced was extracted and applied by real git 2.50.1**:
  `--check` PASS, applied cleanly, `src/validate.js` created with correct content, **`src/main.js`
  untouched so the 28 lines the elided block would have destroyed survive**, and
  `.github/workflows/ci.yml` never created.
- Hunk rejection works: unchecking one hunk moved the delivery from "3 files ready" to "2 files ready".
- All four overlays pass all four dismissal exits at 375px with real touch-type `PointerEvent`s —
  **16/16**, 44×44 hit areas, no displayed `[hidden]` elements, no sideways scroll.
- A full run issues requests for **the page's own assets and nothing else**.
- Manifest resolves with a `maskable` icon and the 180×180 apple-touch-icon; both samples precached;
  `sw.js` contains no IndexedDB.

**Not verified, and stated plainly:** the actual **write-back path** was never exercised. It requires
`showDirectoryPicker` plus a real `requestPermission` grant plus `showSaveFilePicker`, none of which
an automated browser can supply — the picker needs a human. Everything up to and including the bytes
that *would* be written is verified (`applyHunks` is cross-checked against real `git apply` on every
hunk subset), and the write protocol itself — backup gate, plan/write hash check, segment walk,
`createWritable` without `keepExistingData` — is reviewed and unit-tested but has not been run against
a real folder. The read-only path, which is the whole product on Safari, Firefox and iOS, **is**
verified end to end.
