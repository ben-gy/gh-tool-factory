## Idea Source
IDEAS.md (first queued idea). Original text:

> **P2P encrypted video call** — one-to-one and small **one-to-many mesh** video over an encrypted tunnel, from a link + passphrase, no account and nothing hosted. getUserMedia → WebRTC, with per-frame E2E encryption via Insertable Streams/SFrame so even the signalling infra sees only ciphertext, plus a Short-Authentication-String verify step. Local-only **MediaRecorder** capture so a participant can leave with a saved recording. Search intent: "free video call no sign up / no download", "end to end encrypted video chat". Artefact: room link to send + optional local recording file.

## Tool Details
- **Name:** Meetwell
- **Repo:** ben-gy/meetwell
- **Category:** p2p-communication
- **Audience:** Anyone who wants a quick, private face-to-face call without the account/app tax — freelancer↔client, family across borders, or a sensitive (medical/legal/personal) call that shouldn't sit in a corporate cloud.
- **Stack:** Vanilla TypeScript + Vite + Vitest, PWA
- **Browser APIs:** WebRTC (full-mesh RTCPeerConnection + data channels), trystero (nostr strategy), getUserMedia/getDisplayMedia, Web Crypto (PBKDF2/SHA-256 → SAS), MediaRecorder + Canvas.captureStream + Web Audio, Screen Wake Lock, Web Share/Clipboard/qrcode
- **Worker strategy:** main-thread — a live call is inherently event-driven; no CPU-bound batch to offload. (The compositor uses setInterval, not rAF, so recording survives a backgrounded tab.)

## Privacy Model
- **Protected:** camera + mic media (full-mesh, direct browser-to-browser, DTLS-SRTP, no media server in path); the room passphrase (encrypts the signalling handshake + derives the SAS; lives only in the URL hash); nothing recorded unless the user presses Record, and recordings are local files never uploaded.
- **Not protected:** public nostr relays learn an ephemeral room id (not SDP/media — encrypted with the passphrase); IP visible to peers + STUN (inherent to P2P); symmetric-NAT pairs with no TURN relay may fail to connect (no TURN by design); anyone with the full link can join.
- **Trust surface:** static bundle + its TLS; public nostr relays + STUN (encrypted handshake only); cookie-less Cloudflare Web Analytics beacon (page views only); feedback widget (only on explicit Send).

## Architecture Decisions
- **Why nostr strategy, not torrent:** the installed `trystero@0.25.3` is a shim over `@trystero-p2p/*`; its `trystero/torrent` subpath is a deprecated empty stub, while `trystero/nostr` re-exports the real, maintained implementation (public nostr relays for signalling). Both fit the zero-backend model equally; nostr was the one actually available and typed.
- **Dropped the insertable-streams per-frame layer.** The idea called for SFrame per-frame encryption, but trystero constructs its own RTCPeerConnections and doesn't cleanly expose per-sender encoded transforms, and a live encrypted-media call can't be verified in this pipeline. Crucially it's redundant for a full mesh: with no SFU, every media stream is already a direct DTLS-SRTP link and the relay never touches media. The honest, reliable E2E story is **password-encrypted signalling (protects the DTLS fingerprints from a MITM relay) + full-mesh DTLS-SRTP + a human-verified SAS**. Shipping a claim I couldn't stand behind or verify would have been worse than omitting it.
- **Vanilla TS** over React: state (lobby vs call, a participant Map, per-tile mute/level, recording) is real but shallow — a render function over a Map suffices.
- **Screen share via `replaceTrack`** (no renegotiation), reverting on the OS 'ended' event.

## Verification (what was and wasn't proven)
The preview browser blocks camera/mic capture, so **no real camera/mic call was verified in this pipeline** — never described a synthetic pass as a real device call. What *was* verified end-to-end, with **two real browser tabs joining the same room**:
- Peer discovery + WebRTC connection over public nostr relays — each tab saw the other as a participant tile (bidirectional).
- Presence (names, mute state) exchanged over the encrypted data channel; the peer tile showed the remote name.
- Chat messages delivered peer-to-peer (tab B → tab A).
- SAS words derived identically on both sides from the shared passphrase.
- View-only fallback when camera/mic is denied (a first-class path, with an honest note).
- Modals (How/Privacy/About) open/close + Escape; event-log drawer opens and closes via its × and Escape; the `[hidden]` guard holds (drawer `display:none` on load, centre point returns real content); 375px mobile layout (tiles stack to 1 column for ≤2 people, SAS bar fits on one line, no horizontal overflow, no invisible overlay).
- The stale-service-worker trap bit once during iteration (old CSS served); unregistered the SW + cleared caches + hard-reloaded to confirm the fix.

The media-stream send and MediaRecorder recording paths are wired against the same trystero API but could not be exercised without a real camera in the harness.
