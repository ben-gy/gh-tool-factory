## Post-run investigation (Fleet SSL Medic, 08-19)

`crowdsize`'s hold lapsed as planned and the run cycled it once. The script also reported
`NOT ISSUING — crowdsize(72h)`: the 08-16 authorization sat **undisturbed for a full 72 hours** and
never issued. That is the cleanest possible test of cycling — one property, no interference, 28
certificates of measured headroom — and it failed, so the 08-16 question ("is the fresh-hostname
escape real?") is now answered: **no**.

Full write-up in `ssl-root-cause-analysis.md` under **Cause 8 — the stall is GitHub-side and
per-property**. Headline findings:

- **A control pair isolates the variable.** `crowdsize`, `torc` and `au-spectrum` all had their DNS
  records created on **08-15**, same zone, same account, same registered domain. `torc` issued
  07:00Z, `au-spectrum` 13:42Z; `crowdsize` has never started. This rules out every domain-wide
  cause — rate limit, CAA, account block, zone — in a single comparison.
- **Every per-property layer is identical to the issuing controls**: full Pages API object, the
  Cloudflare record (no AAAA on any stalled name), deploy history, and — checked for the first time
  — the **contents** of `public/CNAME`, not just its presence. The "stale CNAME file keeps resetting
  the domain" hypothesis was the best remaining one and is dead.
- **New check: the live HTTP-01 path.** `http://<host>/.well-known/acme-challenge/<token>` returns
  `404` with zero redirects on all eight stalled and all four controls alike. Nothing is blocking
  the path Let's Encrypt actually uses.
- **crt.sh is unusable as a budget cross-check** and was nearly a false alarm — its bulk query is
  truncated at 08-13 and omits certificates confirmed on the wire. Read naively it claims
  domain-wide issuance stopped six days ago, which is false. Details under Cause 8.
- **Zone capacity: 219 records.** The 200-record cap that 08-09/08-10 called the binding constraint
  is no longer binding; every one of the 206 properties has a record.
- **No factory shipped a stalled certificate.** The 08-02 poll fix is holding in all three.

**Conclusion: this is a GitHub-side failure to pick up the certificate request, not a
configuration fault, and it is not fixable from this routine.** It needs GitHub Support, with the
08-15 control pair as the reproduction.
