> **P2P encrypted secret hand-off (burn-after-read)** — send a password, API key, or recovery phrase directly device-to-device over a one-time encrypted channel, verified by an out-of-band Short-Authentication-String, then **burned** — no "paste your secret into a website that emails a link" middleman, no copy persisted anywhere. The safe answer to "how do I securely send someone a password". Distinct from the clipboard hand-off: single-use, MITM-verified, self-destructing. Artefact: confirmed one-time delivery, and proof it's gone.

## Tool Details
- **Name:** Burnwell
- **Repo:** ben-gy/burnwell
- **Category:** p2p-communication (indexed as "privacy" on the hub)
- **Audience:** anyone who Googles "how to send a password securely" — devs sharing API keys, IT sending temp logins, someone passing a Wi-Fi password or crypto recovery phrase.
- **Stack:** Vite 6 + vanilla TypeScript + Vitest
- **Browser APIs:** WebRTC data channel (trystero/nostr), Web Crypto (PBKDF2 + AES-GCM-256 + SHA-256 SAS), Clipboard, Web Share, qrcode, Service Worker (PWA)
- **Worker strategy:** main-thread only — the payload is a short string, so AES-GCM is instant; a worker would add complexity for no benefit. Reuses the fleet's proven crypto/room/eventlog modules verbatim.

## Privacy Model
- **Protected:** the secret is plaintext only inside the two tabs (DTLS on the wire + AES-GCM-256 sealed with a passphrase-derived key); one-time delivery to a single verified recipient then burned (sender's copy wiped, room torn down); passphrase only in the link hash, or (split mode) never transmitted; nothing stored server-side.
- **Not protected:** both parties must be online simultaneously (no store-and-forward — the deliberate price of zero storage); whoever holds the full link first could receive the secret (mitigated by split mode, the SAS, and the one-time "already delivered" alarm); IP visible to the peer + public STUN; symmetric-NAT pairs may fail (no TURN by design); once revealed, the secret is on the recipient's device.
- **Trust surface:** the static bundle + TLS, public nostr relays + STUN (encrypted handshake only), a cookie-less Cloudflare Web Analytics beacon, the feedback widget (only if used).

## Architecture Decisions
- Reused verbatim from the sibling P2P tools (beamwell): crypto (salt rebranded `burnwell:v1`), wordlist, room/link, router, format, eventlog, the trystero ambient decl, and the modal/glossary/drawer chrome. Wrote fresh: the secret envelope (`secret.ts`), the one-time-delivery state machine (`handoff.ts`), the transport session (`session.ts`, four actions: `req`/`secret`/`gone`/`ack`), all views (`ui.ts`), and the controller (`main.ts`).
- The security-critical single-use rule lives in a **pure state machine** so the guarantee is provable by unit test rather than asserted: the sender delivers only when `armed`, transitions to `delivering`, and answers any later `req` with `gone`; the receiver reveals at most once.
- The secret is held only in a module-local variable, nulled the instant it is delivered (sender) or burned (receiver); it is never written to storage, the URL, or the event log, and on the receiver it is assigned via `textContent` (never interpolated into HTML).
- Two link modes (full / split) implemented purely in `buildInviteUrl`'s `includePass` flag.
- Ember/amber accent on near-black — ties to the burn metaphor and reads as a security tool; matches the design-taste bar (Lucide icons, hairlines, one accent, no emoji in chrome).
