## Tool Details

- **Name:** topicgap
- **Category:** data-explorers
- **Audience:** whoever owns a support queue or an LLM product's eval set and has been asked "what do
  people actually ask us?" — ML engineers, support-ops analysts, PMs with a CSV export
- **Stack:** vanilla TypeScript + Vite 7. **Zero runtime npm dependencies.**
- **Browser APIs:** `File.stream()` + `TextDecoderStream`, module Web Workers, Cache API, streaming
  `fetch` with byte progress, Web Share / Clipboard / `<a download>`, service worker (vite-plugin-pwa)
- **Worker strategy:** one dedicated module worker owns the entire pipeline — parse, tokenise, embed,
  cluster, label, score coverage, build artefacts. Corpus text never crosses back to the main thread
  except as the exemplars actually rendered.
- **First-party engine:** safetensors reader, WordPiece tokenizer, embedding pooling, spherical
  k-means++, c-TF-IDF, Porter stemmer, RFC-4180 CSV reader and writer, JSONL ingestion, column
  profiler, coverage maths.

## Privacy Model

- **Protected:** rows and eval set never leave the tab (no upload endpoint exists); nothing written
  to disk — no IndexedDB, no OPFS, no cookies, only the model in the Cache API and settings in
  `localStorage`, enforced by a build gate; cluster labels drop any term appearing in only one row,
  which is where order numbers, ticket references, emails and customer names live.
- **Not protected:** Hugging Face sees two anonymous constant-URL GETs on first run; the Cloudflare
  Web Analytics beacon; feedback when explicitly sent; the user's own exports.
- **Trust surface:** the GitHub Pages bundle + TLS, `huggingface.co` and its `*.hf.co` CDN, the
  beacon, and `feedback.benrichardson.dev`.

## Architecture Decisions

**The model was changed from the queued spec, on measured grounds.** The spec named
`static-retrieval-mrl-en-v1`; it is an excellent *retrieval* model and near-worst for *clustering*.
MTEB v-measure, all 20 cells independently re-verified against the official results repository by two
agents: on `StackExchangeClustering.v2` — the closest public analogue to a support queue —
`potion-base-4M` scores **50.91** against the spec model's **30.39**, and beats `all-MiniLM-L6-v2`'s
45.17. It is also half the download (15,118,424 B), f32 rather than int8, and natively 128-d, so
there is no dequantisation and no Matryoshka truncation loss. It **loses** on long scientific
abstracts, and the How-it-works modal shows the losing rows rather than only the flattering one.

**Spherical k-means, first-party.** Not for speed — a claimed 10.3× advantage over `ml-kmeans` was
checked in research and did *not* reproduce. The reasons are that `ml-kmeans` has no spherical
variant (assignment is equivalent on the unit sphere but the *update* is not: the arithmetic mean
lies strictly inside it and its distances to members stop being cosines), its input type is
`number[][]` so 25,000 × 128 becomes 25,000 JS arrays, and it drags in `ml-matrix` + `ml-spectra-
processing` transitively.

**The map was cut, as the spec demanded.** No UMAP, no WebGL point cloud, no lasso. The consequence
is that the five inline exemplars and the per-cluster quality readout become *mandatory*, not
decorative: they are the only remaining way for a user to falsify the numbers.

## Errors & Resolutions

1. **`config.json` is 8 keys, not 4; the header field is 80 bytes, not 78.** Both from the plan's
   transcription. Corrected against the bytes on the wire.
2. **`tokenizer.json` ships a `TemplateProcessing` post-processor** adding `[CLS]`/`[SEP]` — not
   mentioned in the plan. Honouring it would pool two uninformative rows into every short row's mean.
   No post-processing stage exists in this build; a test asserts it.
3. **CSP needed `https://*.hf.co`** as well as `huggingface.co`, because the model URL 302s to a
   signed CDN URL on `us.aws.cdn.hf.co`. Without it the download dies with only a console violation.
   A build gate now asserts both, plus both feedback origins and both beacon origins.
4. **The competitive claim was materially wrong and is not shipped.** "Apple's embedding-atlas is a
   CLI/npm/Jupyter install" (IDEAS.md) is stale — it is a hosted client-side web app. And a **second**
   free, no-signup, client-side competitor was found that the plan did not know about:
   `graphmykeywords.com` exports a per-row `cluster_label` **and** has a second-file coverage mode
   with a literal `"Only them — gap"` label. So the sentence "nobody takes a second file and reports
   uncovered clusters" is false. The shipped copy states the narrower, verified truth instead.
5. **A self-contradicting headline, caught by the dry-run.** Every uncovered cluster on the demo sits
   below the detection floor, so the UI said "39.9% of your traffic is uncovered" while every cluster
   read "too small to tell" — and the pill *replaced* the word "uncovered", hiding the finding on
   exactly the small clusters that matter. Now both facts show, and the caveat gives the correct
   statistical reading: no single small cluster proves a gap, their combined volume against the
   chance level does.
6. **Five identical exemplars.** The most central members of a cluster are the rows most likely to be
   duplicates, and real corpora repeat heavily. `pickExemplars` and `curationSample` now dedupe by
   normalised text with the quota still filled; the demo sample gained openers and closers so it is
   60% distinct with a maximum of 22 copies, which is realistic.
7. **A mobile layout defect** found by screenshot, not by assertion: the cluster label rendered **one
   character per line**, because the `nowrap` pills and row count won the flex-width fight and
   `overflow-wrap: anywhere` then broke every character. Label box was 4×434 px; it is now 230×22.
8. **My own build gate was wrong about the icon.** It failed `apple-touch-icon.png` for *having* an
   alpha channel. That is the wrong property — an RGBA PNG whose alpha is entirely `0xff` is opaque,
   which is what the shared generator emits. The gate now inflates the IDAT, undoes the PNG
   scanline filters and asserts every alpha sample is `0xff`.
9. **A literal NUL byte got written into `csvwrite.ts`** by my own edit — precisely the invisible
   control-character trap crowdsize documents. Caught, rewritten as a code-point test, and the build
   gate now fails on any literal control byte in `src/`.
10. **Stale service worker on the shared preview port**, twice: the browser served the previous CSS
    bundle and a correct fix looked broken. Diagnosed by comparing the served CSS hash. A fresh port
    (5233, not the fleet-shared 5199) plus explicit unregister-and-clear is the working procedure.
11. **`frame-ancestors` in a `<meta>` CSP is ignored** and logged an error on every load. Removed.

## Known characteristics, stated rather than smoothed away

- **The distance gate is strict.** On the demo, 17 of 36 golden-set rows land outside every cluster's
  radius, because they are written agent-facing ("What should I tell a customer whose delivery is
  running late?") while the corpus is customer-facing ("my delivery is late"). This is surfaced
  prominently in the headline caveat. It is arguably the single most useful thing the tool can say
  about a golden set written in a meeting room, so it is reported rather than tuned away.
- **The demo's measured 39.9–51.3% uncovered volume exceeds the 29.7% planted** in the synthetic
  sample, for the same reason plus imperfect clustering. The chance level (7.2%) and the detection
  floor are always printed beside it, which is the guard against over-reading either number.
- **No real support corpus was used.** The sample is entirely synthetic and first-party; no public
  ticket corpus exists that could be shipped.
