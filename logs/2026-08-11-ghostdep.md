## Privacy Model
- **Protected:** the pasted code never leaves the tab; the popular-name table is bundled
  rather than fetched, so nearest-name search works offline and reveals nothing; no
  IndexedDB/OPFS/cookies; nothing is installed or executed.
- **Not protected:** the package NAMES are visible to npm and PyPI — unavoidable, since
  only the registry owning a namespace can answer the question. Twenty names also imply
  what you are building, and the threat model says so.
- **Trust surface:** GitHub Pages + TLS, registry.npmjs.org, api.npmjs.org, pypi.org,
  the Cloudflare beacon, and the feedback widget only if used.
- **Refuses to say:** whether a package is malicious; that anything is safe; that an
  unchecked name is missing; a PyPI download count.

## Architecture Decisions

**True Damerau-Levenshtein rather than OSA** is a correctness requirement, not taste.
Nearly every npm package with that name implements optimal string alignment, which
answers 3 for `d("ca","abc")` where the truth is 2 and which violates the triangle
inequality. A BK-tree is only correct over a metric; with OSA the failure mode is not an
exception but a neighbour that silently never comes back.

**Endpoints chosen by measurement.** `GET /{name}` on npm is 6,878,486 bytes for react
(2.9 MB even abbreviated); `GET /{name}/latest` is ~2 KB and 404s cleanly. PyPI's simple
index is served at api-version 1.4, i.e. PEP 700, so one request yields existence,
versions, per-file upload-time, size, yanked and sha256 — which is what makes the
`--require-hashes` artefact real rather than aspirational. The full npm packument is
fetched only below 50k weekly downloads: exactly where age matters and where the
document is small.

**The thresholds are the product.** `ms`, `qs` and `ws` are three real, hugely popular
npm packages one edit apart. The edit budget scales with name length and a neighbour
must be far more popular, both exposed as sliders with a live match list.

Bugs the tests and the dry-run caught, all fixed:

1. **BK-tree pruning.** Passing the distance cutoff into the tree's own node comparison
   under-estimates `d` and shifts the child-bucket window down, dropping subtrees that
   contain matches. Verified by reintroducing the bug: **5 of 8 tree tests fail**,
   including the headline `python-dateutils → python-dateutil` case.
2. **`/^https?/` matched `httpx`** — one of the most-installed packages on PyPI — and
   dropped it as a URL, silently, with a reason that read as deliberate.
3. **The wheel-filename matcher built its character class and *then* escaped regex
   metacharacters**, escaping the brackets it had just inserted, so it matched nothing
   for every punctuated project name (`ruamel.yaml`, `zope.interface`).
4. **The import map was applied to `pip install` lines**, rewriting a user's `flask` to
   `Flask` for no purpose, since PEP 503 makes them one project.
5. **The Python import regex lost every name after an `as` alias** in a comma list.
6. **A `const self`** in the worker's message handler would have put the earlier
   `self.postMessage` into a temporal dead zone.
7. **The CSV writer's control-character class was written with LITERAL control bytes** —
   caught by the source-hygiene gate, which is why that gate exists.
8. **The honesty gate fired on its own disclaimer** and is now negation-aware, with a
   self-test proving it still catches a real claim.
9. **`relevantNeighbours` filtered on cost but not on name**, so a neighbour equal to the
   candidate could show if its reported cost were non-zero.

### The DNS blocker, with the audit

`ghostdep.benrichardson.dev` could not be created. The Cloudflare zone
(`bf71cf2904d22db3443bb471e5dbdde2`) is at its hard **200-record cap** and returned
`{"code": 81045, "message": "Record quota exceeded."}`.

The documented reclaim procedure in the `cloudflare-zone-record-cap` memory was followed
in full and **found nothing safe to delete**:

- Zone contents: exactly **200 records** — 187 CNAME, 5 MX, 5 AAAA, 3 TXT.
- The rename-pair shape the procedure looks for (`veilpix` → `veilpix-stego`) yields
  **zero** candidates; those bare names were already reclaimed on 2026-08-05.
- 17 Pages CNAMEs have no same-named repo, but **16 of them are the live claim of a
  renamed property** (`tiltwell-level` is claimed by `tiltwell`, `au-name-trends` by
  `au-baby-names`, and so on) — deleting any would take a live property offline, which
  is exactly the trap the memory records from the metascrub near-miss.
- Enumerating the Pages `cname` of all 324 repos: **185 of 186** Pages CNAMEs in the zone
  are claimed by a live repo. The single unclaimed one is `www.benrichardson.dev`, which
  serves a live 301 and is not mine to delete.

**A side finding worth acting on:** three repos claim hostnames that have **no DNS record
at all** — `collate.benrichardson.dev`, `au-road-deaths.benrichardson.dev` and
`au-cpi-explorer.benrichardson.dev`. Those properties are already dark, which means the
zone has been full long enough that earlier deploys silently lost their DNS too.

### What was done instead

Rather than ship a tool nobody can open, the Vite `base` was changed from `/` to `./`.
With an absolute base every asset pointed at `ben-gy.github.io/assets/…` and 404'd, so
the page loaded blank; a relative base resolves correctly at **both** the repo-path URL
and the custom-domain root. Verified live: `html=200 js=200 sample=200 manifest=200`, and
the full workflow runs.

**To switch to the custom domain, once one DNS slot is free**, nothing needs rebuilding:

```bash
curl -X POST "https://api.cloudflare.com/client/v4/zones/bf71cf2904d22db3443bb471e5dbdde2/dns_records" \
  -H "Authorization: Bearer $CF_TOKEN" -H "Content-Type: application/json" \
  --data '{"type":"CNAME","name":"ghostdep","content":"ben-gy.github.io","ttl":1,"proxied":false}'
gh api repos/ben-gy/ghostdep/pages -X PUT -f cname="ghostdep.benrichardson.dev"
```

Then update the `url` in `registry.json` and `index/tools.json`.

  relative base and documented above. Unresolved at the DNS layer; needs one freed slot.
- **`python3` lacked `sys.stdlib_module_names`** (3.9 on this box) — the generator now
  searches for a 3.10+ interpreter and *fails loudly* rather than silently emitting a
  short stdlib list, which would have sent ghostdep to PyPI asking whether `graphlib`
  exists.
- **The npm crawl converged at 2,873 names** with a 619/week floor, because a dependency
  crawl finds the packages other packages *depend on*, not the CLIs and frameworks an
  assistant tells you to *install*. Added a 702-query search harvest: 93,213 names,
  ranked by real weekly downloads, top 5,000 kept, floor now **125,352/week**.
- **A stale service worker** served the old bundle during the dry-run and made two fixed
  bugs look unfixed — the recurring preview trap. Unregister *and* clear caches, then
  reload.
- **The preview tab reports `innerWidth: 0`** until explicitly resized, so the first
  overlay sweep produced a false failure from a leftover backdrop. Re-run from a clean
  page with an explicit viewport.
