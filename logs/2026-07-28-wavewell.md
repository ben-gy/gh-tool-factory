## Idea Source
Researched. IDEAS.md was empty. Reviewing the last several registry entries showed a run of
file-in/file-out **image** tools (ditherwell, vectorwell, embiggen) preceded by a cluster of sensor
tools. Applying principle #6's "what if the input weren't a file / break the admin-console register"
check, I looked for a creative tool with a strong *shareable* artefact that the fleet doesn't cover.

The fleet has many video **consumers** (vidwell compress, gifsmith, blurwell) but nothing that
**generates** video. An **audiogram / waveform-video maker** (audio → shareable MP4) is high-demand
("audiogram maker free", "waveform video for instagram"), privacy-relevant (podcasters currently
upload unreleased episodes to paid SaaS like Headliner/Wavve), leverages WebCodecs *encoding from
scratch*, and leaves the user with an MP4. Googleable, novel, artefact-producing — all five idea
criteria clear.

## Tool Details
- **Name:** Wavewell
- **Repo:** ben-gy/wavewell
- **Category:** media-tools
- **Audience:** Indie podcasters, musicians and creators clipping audio for Instagram/TikTok/X/LinkedIn/YouTube who don't want to upload unreleased audio to a paid SaaS.
- **Stack:** Vanilla TypeScript + Vite 6 + Vitest
- **Browser APIs:** WebCodecs (H.264 via mediabunny CanvasSource), mediabunny Output/Mp4/BufferTarget mux, mediabunny AudioSampleSource (AAC, planar f32) + @mediabunny/aac-encoder, Web Audio decodeAudioData + AudioBufferSourceNode preview, OffscreenCanvas + Canvas 2D, Web Workers, first-party FFT/DSP, File System Access, Web Share, Clipboard, Service Worker (PWA).
- **Worker strategy:** decode on the main thread (a worker can't construct an AudioContext), transfer channel-data copies + settings to a single dedicated worker that owns the OffscreenCanvas render + mediabunny encode; postMessage progress, no rAF (avoids the hidden-tab hang).

## Privacy Model
- **Protected:** the audio file, decoded samples, caption and any background image — all decoded, analysed, drawn and encoded in the tab; the MP4 is only saved/shared on an explicit click.
- **Not protected:** page load is a normal request (GitHub Pages CDN sees the IP); recipients of a shared video receive it.
- **Trust surface:** static bundle + TLS to GitHub Pages; cookie-less Cloudflare Web Analytics beacon (anonymous page views only, never the audio); feedback only when the user presses Send.

## Architecture Decisions
- **mediabunny for encode/mux** (not ffmpeg.wasm): needs no COOP/COEP headers, which GitHub Pages can't set. This is the fleet's first tool that *generates* video (CanvasSource) rather than transcoding it — verified the CanvasSource + AudioSampleSource API against the installed d.ts before building.
- **Audio via AudioSampleSource, not AudioBufferSource:** `AudioBuffer` isn't reliably constructible inside a Worker, so audio is fed as planar-f32 `AudioSample` chunks (1s each) built from transferred channel data — no AudioContext needed worker-side.
- **avc capability gate:** `getFirstEncodableVideoCodec(['avc'])` returns null on browsers without H.264 encode (Firefox); the UI says so up front rather than failing silently.
- **DSP is a pure, tested module:** radix-2 FFT + Hann window + log-spaced spectrum banding drives the bars; a whole-clip peak-envelope drives the sweeping waveform; attack/release smoothing keeps the bars lively but not jittery. All unit-tested with synthetic tones.
- **Render code shared** between the worker (OffscreenCanvas) and the main-thread live preview, so what you preview is what you export.
- **Vanilla TS** (no React): one preview stage + a settings rail — no deep component tree.
