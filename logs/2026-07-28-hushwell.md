Podcast Enhance, Krisp, cleanvoice.ai, all of which upload your audio). That's the strongest
possible privacy narrative — voice recordings are personal (interviews, calls, therapy
notes) — so it's a perfect fit for this factory. Confirmed the in-browser approach is viable
with `@shiguredo/rnnoise-wasm` (RNNoise recurrent-net denoiser; inlined wasm, offline API:
`Rnnoise.load()` → `createDenoiseState()` → `processFrame(Float32Array)` per 480-sample
frame, returns a VAD score).

## Tool Details
- **Name:** Hushwell
- **Repo:** ben-gy/hushwell
- **Category:** media-tools (index category: media)
- **Audience:** journalists, podcasters, students, anyone with a confidential recording they
  can't hand to a cloud enhancer.
- **Stack:** Vite 6 + vanilla TypeScript + Vitest
- **Browser APIs:** WebAssembly (RNNoise), Web Audio (decodeAudioData / OfflineAudioContext),
  AudioWorklet (mic capture), Web Workers + Transferable ArrayBuffers, AudioBufferSourceNode,
  Canvas 2D, File System Access / Web Share / Clipboard, Service Worker.
- **Worker strategy:** dedicated denoise worker (RNNoise loop, streaming determinate
  progress) + separate WAV/MP3 encode worker; AudioContext/OfflineAudioContext + AudioWorklet
  on the main thread (workers can't construct an AudioContext).

## Privacy Model
- **Protected:** audio is decoded, denoised and encoded entirely in the tab — never
  uploaded; the model ships inside the page so cleaning makes no network request; works
  offline after first load.
- **Not protected:** the initial page load is a normal GitHub Pages request over TLS; an
  anonymous cookie-less Cloudflare Web Analytics page-view beacon; feedback only if the user
  opens the form and presses Send.
- **Trust surface:** the static bundle (hash-pinned by the deploy), the TLS chain, the
  RNNoise WASM (Apache-2.0) running locally.

## Architecture Decisions
- **RNNoise over a first-party spectral gate.** The fleet loves first-party FFT DSP, but the
  one-click "magic" UX that Googlers want (no noise-profile capture step) is exactly what
  RNNoise gives, and it's the same model the incumbents' free tiers use. The wasm is inlined
  into its JS chunk (self-contained, no separate .wasm to serve), so offline is just a matter
  of precaching that chunk (bumped workbox `maximumFileSizeToCacheInBytes` to 8 MB for the
  4.8 MB chunk).
- **Record-then-process, not live monitoring.** Denoising the mic live would hit the iOS
  earpiece-routing trap (voxwell #4) and monitor feedback. Instead the mic is captured to raw
  PCM via an import-free AudioWorklet that is *never connected to the destination*, then run
  through the identical offline pipeline as an uploaded file. Denied mic permission lands in
  the file-upload path as a first-class fallback.
- **48 kHz mono pipeline.** RNNoise is trained at 48 kHz; decode → downmix → resample to
  48 kHz via OfflineAudioContext (linear-resampler fallback), output stays 48 kHz mono.
- **The "reduced by N dB" number** comes from a VAD-gated noise-floor estimate: RNNoise's
  per-frame VAD score marks speech frames, and we take the low-percentile RMS of the
  remaining (gap) frames before vs after. That's the artefact-beyond-the-file that makes the
  result legible.
- **Vanilla TS, no React** — single linear input→process→output workflow.
