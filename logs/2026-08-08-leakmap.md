**Thirty-five numbered corrections to the spec came out of it.** The duplication lens returned

## Privacy Model

- **Protected:** `.env` and build files are read, indexed and searched in the tab; no endpoint
  receives either. No value is ever tested against a live API. Every value in every artefact is
  masked and there is no reveal control. Nothing goes in the URL. Exactly one persisted key,
  `leakmap.theme`.
- **Not protected:** masking is a spill guard, not a security boundary; "not found" means "not found
  verbatim"; leakmap saw a folder, not a deployment; `recovered-source.zip` is unmaskable by
  construction and that is the finding; index maps are refused, not guessed; brotli is named and
  counted, not scanned.
- **Trust surface:** the GitHub Pages bundle and its TLS chain; the Cloudflare Web Analytics beacon;
  `feedback.benrichardson.dev` on Send only. The CSP proves no fourth destination exists — it cannot
  prove what is sent to the two that do, and the copy says exactly that.

## Architecture Decisions

Vanilla TS because the state is one scan result. `fflate` is the only runtime dependency; the two
riskiest engines (Aho–Corasick and the VLQ decoder) are first-party, and in the VLQ case that was
forced rather than chosen — `@jridgewell/sourcemap-codec@1.5.5` silently promotes malformed 2- and
3-field segments to `[0,0,0,0]` (a fabricated attribution to `sources[0]:1:0`) and `source-map@0.8.0`
crashes outright on an out-of-range index, which is disqualifying for something that ingests
untrusted maps in a browser tab.

Aho–Corasick was kept for the honest reason rather than the flattering one: measured, it is FLAT at
362–378 MB/s regardless of pattern count and `indexOf` is about 4× faster at P=5. It wins here
because variant enrolment pushes a 15-secret `.env` to 40–90 patterns, past the measured crossover,
and because it streams `Uint8Array` chunks against a fixed table instead of materialising a file as
a string.

- Suites: `vlq` (18), `mappings` (16), `matcher` (18), `env` (36), `safety` (~40), `shapes` (29),

**Failures during development that were real bugs, not test noise** — recorded because each one
changed shipped behaviour:

1. **`safeEntryPath` rejected every `..`, so source recovery produced NOTHING on a normal Vite
   build.** `sources: ["../../src/live.js"]` is the *ordinary* shape — the map lives in
   `dist/assets/` and the source is two levels up. The unit test missed it because it had encoded
   the same wrong rule; the end-to-end run over a real build caught it. Leading `..` is now dropped
   (capped at four), `..` after a real segment is still refused rather than popped.
2. **Context-window scrubbing had both clipping directions inverted**, leaving 28 characters of a
   neighbouring secret in the output. Both directions are now checked on both fields, with a test
   pinning the case.
3. **The high-entropy elision rule ate ordinary minified property chains.** Re-measured: camelCase
   case-flip density tops out at 0.367 across real identifiers, random all-alphabetic runs sit at a
   0.500 median, and only 0.696% of random 24-char base64 runs carry no digit at all. Threshold set
   at 0.42, with the residual miss rate stated in the code rather than hidden.
4. **The CSV formula guard did not force quoting**, so the apostrophe could be stripped by an
   importer and the formula restored.
5. **Three of my own test fixtures were wrong, not the code** — a gate rung, a family count, and
   three keys built from `'a'.repeat(58)` that leakmap's own placeholder gate correctly rejected.

**A literal U+2028 and a literal `*/` ended up inside my own source comments** and broke the
TypeScript parse — which is, fairly, exactly the class of bug `charsight` exists to find.
