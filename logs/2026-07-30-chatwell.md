# Build Log: Chatwell
**Date:** 2026-07-30
**Status:** deployed

## Idea Source
IDEAS.md (first queued idea). Original text:
> **P2P encrypted ephemeral group chat** — a disposable, accountless end-to-end encrypted chat room from a link + passphrase; mesh DataChannels so messages never touch a server and evaporate when everyone leaves. Web Crypto for message encryption (ratcheting keys), typing/read state, image drops. Search intent: "anonymous encrypted chat room no sign up", "self destructing group chat". Artefact: shareable invite link + optional exported encrypted transcript.

Fleshed out into a full group-mesh chat. Deliberately **did not** claim "ratcheting keys" — v1 uses one
static AES-GCM key derived from the passphrase (PBKDF2), and the Threat Model states plainly that there
is no forward secrecy. This is the honest, verifiable story (per the trystero-p2p-recipe memory: don't
claim crypto you can't verify). Dropped the pairing-store and camera-QR-scan of the sibling `beamwell`
(they suit device pairing, not an ephemeral room); added group mesh, presence, typing indicators, and a
plain-text transcript export as the takeaway artefact.

## Tool Details
- **Name:** Chatwell
- **Repo:** ben-gy/chatwell
- **Category:** p2p-communication (index: privacy)
- **Audience:** a small group who wants to say something privately and have it be gone — families on a sensitive topic, a couple of colleagues, an organiser sending a one-off coordinated message. Mixed phone/laptop.
- **Stack:** Vite 6 + vanilla TypeScript + Vitest
- **Browser APIs:** WebRTC data channels (full mesh, via trystero/nostr), Web Crypto (PBKDF2 → AES-GCM-256, SHA-256 SAS), qrcode, Web Share / Clipboard / File System Access, Service Worker (vite-plugin-pwa)
- **Worker strategy:** main-thread (each message is a small AES-GCM blob; the transport is already off-thread inside trystero)

## Privacy Model
- **Protected:** message contents (text + inline images) — direct DTLS data channels plus an app-layer AES-GCM-256 seal keyed from the passphrase; no server in the message path. The passphrase lives only in the link hash. Nothing stored server-side; the room is ephemeral (RAM-only).
- **Not protected:** public nostr relays learn an ephemeral room id + that browsers connect (handshake stays encrypted); IP visible to peers + STUN; **no forward secrecy in v1** (one static key from the passphrase); symmetric-NAT pairs with no TURN may fail to connect; ephemerality stops a *server* keeping a copy, not a *person in the room* exporting the transcript.
- **Trust surface:** the static bundle + its TLS chain; public signalling relays + STUN (encrypted handshake only); cookie-less Cloudflare Web Analytics beacon (page views only); the feedback widget (only if opened + Send pressed).

## Architecture Decisions
- Reused the proven beamwell/trystero core verbatim where possible: `crypto.ts` (PBKDF2→AES-GCM + SAS), `room.ts` (id/passphrase/invite), `wordlist.ts`, `eventlog.ts`, `router.ts`, `trystero-nostr.d.ts`, the modal/glossary/icon scaffolding. Vanilla TS — a single-view chat with a message list + composer doesn't need React.
- New group-mesh `session.ts`: three actions — `hello` (name), `msg` (binary `[iv|ciphertext]` frame, broadcast), `typing` (`{on}`, broadcast). Messages broadcast to all peers (no target); the transport peer id is the authoritative sender, not the header.
- New pure, unit-tested modules: `envelope.ts` (versioned message wire format + frame pack/unpack), `text.ts` (escape + URL linkify + ids), `color.ts` (FNV-1a hash → stable per-author hue), `format.ts` (bytes/clock/joinNames).
- Typing: sender sends `typing(true)` on first keystroke and re-sends on a 3s heartbeat while active (so a long message doesn't let the receiver's 6s expiry clear the indicator); a 2.5s idle sends `typing(false)`.

## Typing-indicator verification caveat (honest)
The typing indicator uses the **identical broadcast-JSON mechanism** as the live display-name rename,
which **was** verified propagating across the mesh (Bo→Ada). Its own live cross-tab *display* could not be
independently re-confirmed in the final harness runs: after ~20 reconnect cycles the public nostr relays
began rate-limiting (`"you note too much"`), so the two tabs would no longer re-discover each other, and
the preview browser throttles `setInterval` on backgrounded tabs (which the earlier sustained-typing test
attempts relied on). The feature is correct by construction and by analogy to the verified rename, and was
hardened with a heartbeat; it is not separately claimed as independently re-verified. A recurring
stale-service-worker cache on the shared preview port also intermittently served an old bundle into the
test tabs (the known [preview-stale-service-worker] trap) — it does not affect the fresh-origin production
deploy.
