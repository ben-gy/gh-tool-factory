## Tool Details
- **Name:** Syncwell
- **Repo:** ben-gy/syncwell
- **Category:** p2p-communication (privacy in the public index)
- **Audience:** Privacy-conscious Chromium users who want a folder mirrored laptop↔phone (or with one peer) without a cloud account.
- **Stack:** Vanilla TypeScript + Vite + Vitest
- **Browser APIs:** File System Access, WebRTC data channels (trystero/nostr), Web Crypto (PBKDF2→AES-GCM-256, SHA-256), Web Workers, qrcode/Web Share/Clipboard, Service Worker (PWA)
- **Worker strategy:** one dedicated crypto worker (encrypt/decrypt/hash), transferable buffers

## Privacy Model
- **Protected:** file contents (AES-GCM-256 keyed from the passphrase, on top of the channel's DTLS); passphrase (link-hash only, never sent); file names/sizes/times (encrypted manifest on the data channel).
- **Not protected:** IP visible to peer + public STUN; ephemeral room id on public nostr relays; symmetric-NAT pairs may fail (no TURN by design); the sync peer sees the files you sync.
- **Trust surface:** static bundle + TLS to GitHub Pages; public nostr relays + STUN (handshake only); Cloudflare Web Analytics beacon (anonymous page views; files never sent); feedback widget (only if the user sends).

## Architecture Decisions
- Reused the proven trystero(nostr) + PBKDF2/SAS scaffold from the castwell/talkwell/meetwell siblings (session, crypto, room, router, wordlist).
- **Pull-based protocol** (each side requests what the other holds newer/unique) so a file is never sent twice and the two sides never race — simpler and more robust than proactive push.
- **Version ledger** (`ledger.ts`): the File System Access API cannot set a written file's mtime, so a received file lands with a fresh mtime and would look "newer" → a sync ping-pong. The ledger remembers each synced file's origin mtime and reports it for untouched files; a size change or a clearly-later disk mtime marks a real local edit. This is the key correctness insight and is unit-tested.
- **Never deletes:** a vanished path is simply no longer offered — a deliberate safety guarantee that removes a whole class of destructive bugs and is advertised in the UI.
- **Path safety** (`pathsafe.ts`) is a hard security boundary: a remote peer supplies the write path, so `../`, absolute paths, drive letters, control chars and Windows reserved names are all rejected before any `createWritable`.
- Whole-file AES-GCM (not chunk-streamed) with a 512 MB per-file guard — right for documents/code/photos; block-level delta and huge-file streaming are explicit non-goals for v1.
- Files-only fallback (`<input webkitdirectory>` + downloads) is a first-class path on non-Chromium browsers.

## Two-tab verification (real relays)
The native folder picker can't be automated, so — per the P2P recipe — an in-memory folder store
(`MemStore`, behind a namespaced `window.__syncwellTest` hook) drove the **real** engine: real Web
Crypto, real WebRTC data channels, real public nostr relays.

- Two tabs joined the same room; identical 4-word SAS on both (`maple apple olive orbit`) → shared secret confirmed.
- **Two-way sync:** Laptop (2 files) ↔ Phone (1 file) → both ended holding all 3 files; decrypted content byte-exact on both sides.
- **No ping-pong:** stayed "In sync" with 3 transfers / 3 files across ~12s (multiple 3s poll cycles) — the ledger holds.
- Privacy modal opens (header button labelled "Privacy"), How-it-works has 6 steps, event drawer opens + closes via × and Escape, `[hidden]` guard verified (`elementFromPoint` at centre returns real content), mobile 375px has no horizontal scroll and a reachable drawer close. No console errors.

**No real cross-device sync over the internet was tested** in this pipeline (single machine, two tabs over the real relays). The core protocol, crypto, transport and UI are all proven; only true multi-device NAT traversal in the wild is unverified.

## Errors & Resolutions
- **`store` unused local** broke the first `tsc` build (noUnusedLocals) — removed the redundant module-level variable (the engine owns the store).
- **Stale service worker** at localhost:4196 served a cached *castwell* shell on first preview load — unregistered the SW, cleared caches, hard-reloaded (the recurring [[preview-stale-service-worker]] trap).
- Control-character path check initially embedded literal control bytes via a regex literal — rewrote as an explicit `charCodeAt` loop for robustness.
