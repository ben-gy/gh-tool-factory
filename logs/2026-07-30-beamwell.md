## Idea Source
IDEAS.md — the first queued idea (now removed):

> **P2P encrypted device hand-off (clipboard/QR pair)** — pair two of your own devices once by
> scanning a QR, then instantly push text, links, images, or a one-time code between them over an
> encrypted channel — "send this to my phone" with no cloud clipboard and no account. Persistent
> pairing so it's one tap after setup. Uses Web Crypto + DataChannel + BarcodeDetector/getUserMedia
> for the QR. Artefact: the content lands on the other device; a saved pairing link for next time.

Fleshed out into **Beamwell**, a private device-to-device clipboard bridge.

## Tool Details
- **Name:** Beamwell
- **Repo:** ben-gy/beamwell
- **Category:** p2p-communication (privacy in the public index)
- **Audience:** anyone juggling a laptop and a phone who constantly moves a snippet/code/photo across
- **Stack:** Vite 6 + vanilla TypeScript + Vitest
- **Browser APIs:** WebRTC data channel (trystero/nostr), Web Crypto (PBKDF2 → AES-GCM-256 + SHA-256 SAS), BarcodeDetector + getUserMedia (camera QR pairing — the sensor input), qrcode, Clipboard, Web Share (level 2), File System Access, Service Worker (vite-plugin-pwa)
- **Worker strategy:** main-thread — each item is a small AES-GCM blob, so a worker would only add latency; the transport is already off-thread inside trystero

## Privacy Model
- **Protected:** item contents travel over a direct DTLS data channel and are additionally sealed in AES-GCM-256 with a passphrase-derived key — no server in the item path, plaintext only in the two tabs. Passphrase lives only in the link hash. Camera used only to decode the pairing QR on-device; camera released the moment a code is read.
- **Not protected:** public nostr relays learn an ephemeral room id (handshake is passphrase-encrypted); IP visible to the paired device + STUN; symmetric-NAT-with-no-relay may fail; a remembered pairing (room+pass) sits in localStorage.
- **Trust surface:** static bundle + TLS to Pages; public relays + STUN (encrypted handshake only); cookie-less Cloudflare beacon; feedback only when sent.

## Architecture Decisions
- Reused the proven trystero-nostr P2P recipe from the sibling fleet (syncwell/meetwell): `trystero/nostr` (not the deprecated `/torrent` stub), the makeAction-object API, password-encrypted signalling + full-mesh DTLS + a deterministic four-word SAS instead of insertable-streams.
- **Data-transfer variant, not media:** a single binary `frame` action carries `[iv | AES-GCM(envelope)]`; a `hello` (name) and `ack` (delivery receipt) round it out. The envelope is a pure, versioned `[version|headerLen|headerJSON|payload]` buffer — text/link/code items carry their text in the header with an empty payload; images ride as the payload. Keeping encode/decode + frame pack/unpack pure made the whole wire format unit-testable end-to-end.
- **Two-device enforcement:** the first remote peer becomes the primary; any extra peer raises a visible warning and is ignored for messaging.
- **Persistent pairing** kept in localStorage (upsert-by-room, touch, forget), pure over an injected storage so it is unit-tested without a browser.
- Camera QR scan is a first-class *optional* sensor input gated behind `supportsScan()` (BarcodeDetector + getUserMedia + secure context); open/paste-the-link is the first-class fallback everywhere else.
