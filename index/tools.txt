Toolwright
  https://toolwright.benrichardson.dev
  You wired fourteen tools into an agent and OpenAI answered "'additionalProperties' is required to be supplied and to be false". You added it, and now Gemini answers 'Unknown name "additionalProperties"'. That is not bad luck, it is the shape of the whole problem: the single most-Googled repair in this space is itself a Gemini-breaking change, because additionalProperties:false is required by OpenAI strict, required by Anthropic strict, and does not exist in Gemini's parameters schema at all. Paste an MCP tools/list result, an OpenAI tools array in either shape, an Anthropic array or a Gemini functionDeclarations block, and Toolwright walks every node against eleven real targets — not three, because the tool shape and the accepted keywords vary independently, so a belt can be legal on one API of a provider and rejected by the other. You leave with the repaired files for each target, a llama.cpp GBNF grammar built by a first-party port that matches llama.cpp's own test corpus byte for byte, and a post-parse-checks.ts asserting exactly the constraints constrained decoding cannot enforce. It counts no tokens and fetches nothing: two of the three providers have no client-side tokenizer, so two of three columns would have been fabrications — and cutting them is what lets the page promise that nothing you paste ever leaves the tab. 188 of its 689 rule cells read "unknown", because that is what the documentation actually supports.
  Tags: llm, json-schema, function-calling, mcp, gbnf, developer-tools, privacy
  Repo: https://github.com/ben-gy/toolwright

Backslide
  https://backslide.benrichardson.dev
  You changed one line of a system prompt, re-ran your eval, and the pass rate went from 94% to 91%. Now you have two files of a few hundred rows each and no idea which three per cent moved or why. Drop both into Backslide and it lines the rows up, checks only the things that can honestly be called worse — did it stop parsing, did it stop matching your schema, did an assertion your own harness already recorded flip, did it error or get cut off at the token limit — and hands back just the broken subset, with the reason attached and a report you can paste into the pull request. Everything happens in the tab, which matters here more than usual: an eval output holds your prompts, your customers' inputs, your model's answers and often a reference set you paid someone to write. Two things separate it from a spreadsheet formula. It aligns agent tool-call sequences rather than comparing them position by position, so one extra step at index 2 costs one gap instead of marking the next thirteen steps as broken — and an extra step is reported as a divergence, never a regression, because a longer path is not a worse path. And it refuses to guess: when two rows cannot be told apart it says so, and when nothing in your files can be objectively checked it says that too, instead of printing a confident "nothing got worse".
  Tags: llm, evals, regression-testing, diff, developer-tools, privacy
  Repo: https://github.com/ben-gy/backslide

Loraprep
  https://loraprep.benrichardson.dev
  Half of a LoRA training set is usually the same photo four times — burst frames off a phone, a shot re-saved at a lower quality, a thumbnail that came back from someone's email, three screenshots that got mixed in. Cleaning that up is most of the work of preparing a dataset and none of the interesting part, and the alternative is renting a cloud GPU to run a Python script you did not write, on photographs you would rather not upload: faces, client photography, a product that has not shipped. Drop the folder into Loraprep instead and it groups the near-identical frames on your own machine, picks the least-compressed in-focus copy of each, and hands back a zip laid out for kohya_ss and Hugging Face — with a report naming every image it set aside and the file it was judged against. What it will not do is the thing every AI deduplicator does: cluster CLIP embeddings and delete the extras. Measured on the standard LoRA reference sets, two genuinely different photographs of one subject score 0.99 similarity while a real duplicate that has been mirrored scores 0.88, so no cutoff separates them — the model ranks pairs for you to look at, and never removes anything itself.
  Tags: images, lora, training-data, deduplication, machine-learning, privacy
  Repo: https://github.com/ben-gy/loraprep

Scrubjay
  https://scrubjay.benrichardson.dev
  You are three hours from uploading four gigabytes of support transcripts to a fine-tuning provider, someone asks "has anyone checked this for keys?", and you have no answer — because you do not know what a customer pasted into a chat two years ago. Every hosted scanner has the same absurdity at its heart: uploading the file to learn whether the file is safe to upload IS the disclosure you were trying to avoid. Drag the file into Scrubjay instead and it streams the whole thing through 27 recognisers on your own machine, then hands back a copy where personal data has become stable pseudonyms (so it still trains, and rows still join), credentials are destroyed, a findings report tells you exactly where each one was, and an encrypted map lets only you reverse it. It never tests a key against a live API, because checking means transmitting. And it tells you what it cannot do first rather than last: there is no language model in it, so it finds no names and no postal addresses at all, and a clean report means nothing matched — not that the file is clean.
  Tags: privacy, secrets, pii, dataset, jsonl, redaction, developer-tools
  Repo: https://github.com/ben-gy/scrubjay
